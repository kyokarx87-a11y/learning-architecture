# AIと演習を始める

Python 3.9以上、標準ライブラリのみ。リポジトリのルートから実行する。
Claude Code / Codexでこのフォルダを開き、次のように依頼する。

> AGENTS.mdに従い、数学の数列を1問ずつ演習してください。
> 問題と確認用の解答は私が提示します。自己評価の回答を待って記録してください。

1. 自分が使用できる問題と解答を用意する。`local/pool.txt` に**指定科目・単元だけ**の
   問題IDを1行1件で書く。問題IDはその科目・単元内で一意にする。
   公開サンプルプールは数学・数列用のCLIデモであり、実教材ではない。
2. セッション開始・再開時に `python src/session.py status` を実行する。
   進行中ならその問題を再開し、自己評価が未回答なら本人に尋ねる。
3. 次で候補を1問選び、進行中として保存する。

   ```bash
   python src/session.py start --pool local/pool.txt --subject math --unit 数列
   ```

4. 選ばれたIDに対応する問題文・条件・出典を確認し、問題だけを出す。
   生徒の返信を待つ。対応する教材がなければ本人に提示を求め、出典を捏造しない。
5. ヒントを出す前に `python src/session.py hint` を実行する。
   成功した回数に対応する段階のヒントを出し、また返信を待つ。
   4回目はCLIが拒否する。解説時は「解答です。」と宣言する。
6. 判定と教師評価を示し、本人の自己評価（◎〇△×）を尋ねて返信を待つ。
   本人の回答後に、たとえば次で記録する。

   ```bash
   python src/session.py finish --outcome correctWithHints --teacher-eval 〇 --self-eval ◎ --stumble execution --error-category 計算ミス
   ```

   自力正解なら `--outcome correct --stumble none` とし、誤答分類を付けない。
   1問ごとにfinishの成功を確認してから次へ進む。`correctRetry` は一度誤答した後の
   再解答で正解、`failed` は解説を見ても自力完遂に至らなかった場合。
   ヒント後の初回解答で正解した場合だけ `correctWithHints` とする。
7. 終了時に以下を実行し、次回取り組む弱点を1つ本人と決める。

   ```bash
   python src/ledger.py report --ledger local/ledger.jsonl
   python src/ledger.py diagnose --ledger local/ledger.jsonl
   ```

## 実行で守れること・会話に依存すること

`session.py` は未記録問題のあるstart、4回目のhint、評価の不足、
ヒントありの自力正解記録を拒否する。状態は `local/session.json`、
履歴は `local/ledger.jsonl` に保存する。台帳追記後の中断はattempt_idで回復し二重記録しない。
1人・1プロセスずつ使う。同じ状態・台帳への同時書込みは非対応。

CLIは**生徒が実際に回答したか、自己評価を本人が選んだか、ヒントが適切か、
採点が正しいかまでは検証しない**。AIがコマンドを呼ばず出題することも、
直接ファイルを書き換えることもOSレベルでは阻止しない。共通CLIを使う手順契約であり、
Claude専用フックやCodex側の強制ゲートを配備したものではない。
再開時に会話を失っていれば状態ファイルから答えを推測せず、本人に解答状況を確認する。

## 復習と成績向上の確認

新規優先なので、未演習が常に残るプールでは復習が先送りになる。
次回は前回の△×のIDだけを入れた `local/review_pool.txt` でstartするなど、
復習枠を別に確保する。復習日程の自動計算は未実装。

演習直後のヒント込み正答率だけで定着と判断しない。日を空けてヒントなしで解き直し、
自力正答率と同じ誤答の再発を比較する。試験への転移は別の未見問題を同じ時間条件で
解いて確かめる。模試・試験の得点、時間、出題範囲は本人の手元で比較する。
この公開デモに成績改善の実証データはなく、レベル提案の閾値も運用上のルールである。
