# 公開版ハーネスの評価（2026-10-24）

## 判定

成績向上を目指す仕組みの設計は目的に沿う。二軸評価と上流の躓きの記録により、
「何を直すか」を正誤より細かく扱える。ただし変更前は仕組みを説明する見本版であり、
AIが使う実行入口・演習の状態・記録の完全性が欠けていた。
今回、共通CLIで1問ずつ進める最小限のハーネスとして利用可能にした。

## 確認した欠陥と対応

| 変更前の問題 | 対応 |
|---|---|
| AIの読込入口と再開手順がない | AGENTS.md、CLAUDE.md、演習手順を追加 |
| 自己評価や躓きを省略しても追記できる | 新規追記の必須項目と整合性を検査。旧記録の不足件数を診断表示 |
| 未記録のまま次の問題へ進める | session.pyで進行中の1問を保存し、finish前のstartを拒否 |
| 復習候補が指定プール外に漏れる・単元が部分一致する | 科目と単元の一致、プール内、一意な候補だけに制限 |
| 異なる科目・単元で10問窓が混ざる | 科目・単元別に降段を提案、自力正答率も表示 |
| 読込時に不正なJSON構造や語彙を検査しない | 行番号付き検証。壊れた台帳への追記を拒否 |
| ローカルの個人記録を公開し得る | local/をGit除外。追跡済みPythonキャッシュを除去 |
| 回帰検査の自動実行がない | Linux/Windows、Python 3.9/3.14のCIを追加 |

README、docs全件、src全件、テストと架空データを読了し、候補漏れと欠損記録の受入れを
変更前に再現した。原本Vaultの教材・個人演習履歴は評価・転載していない。

## 学習効果の確認方法と今後の拡張

公開データは、動作を示すための架空のサンプルである。
学習効果の確認方法として、ヒントなしの自力正答率、日を空けた再演習、未見問題での確認を想定している。
ヒント使用後の成功と自力での成功を分け、未見問題は時間条件を揃えて解く。

今後の拡張として、復習日程の自動計算、自動昇段、難度データとの連携、時間の記録、
到達目標や試験配点への最適化を予定している。
現行の未演習優先規則を維持したため、復習は別プールで枠を確保する。
このCLIは、開始・ヒント・終了の手順と、評価の入力の整合性を検査する。
解答の採点と内容の確認、教材との照合は、人が行う。
1人・1プロセスずつ、生徒と確認する人が演習に参加して使う。

- 実CLIでstart → hint → finish → statusを実行し、1件追記後にreadyへ戻ることを確認。
- READMEのreport / diagnose / 候補選定を実行。科目・単元別集計、評価乖離、候補IDを確認。
- 独立レビューで状態パスの衝突、カテゴリ語彙、旧記録の診断不足判定を確認し修正。
- Linux / Python 3.9を含む実行はGitHub Actionsで検証する。

## 外部レビューを受けた修正

前回の「記録漏れ防止」という説明は範囲が広すぎた。sessionの検査を実装した一方で、
READMEに残したledger.py addが演習状態を通らず追記できる公式の迂回経路になっていた。
ヒント2回の途中でもcorrectで追記でき、続けてfinishすれば同じ問題が二重に数えられた。
また、教師評価◎とヒント使用、correctと躓き・教師評価×の矛盾を検査していなかった。

修正ではaddを廃止してfinishだけを公式の追記入口とし、共通validateで
ヒント数・outcome・教師評価・躓きの整合性を検査する。同一attempt_idの二重記録も拒否する。
再演習は異なるattempt_idの有効な履歴として残し、集計には演習回数・異なる問題数・
初回正答率・最新正答率を明記する。attempt_idのない旧行の重複は推測で削除しない。

外部指摘の回帰テストは修正前に失敗し、修正後に通過した。前回の23件成功は、
これらの記録経路と項目間整合性をテストしていなかったため、保証の根拠として不足していた。
今後の拡張として、時間の記録、復習日程の自動計算、難度データとレベル変更の連携を予定している。

再修正後は31テストがローカルで成功。CLIでヒント付き問題へのadd拒否、
不整合なfinishの拒否時に台帳・状態が変わらないこと、その後の正しいfinishで1件だけ記録されることを検証した。
独立レビューでも、公式CLIに限った保証と旧履歴互換の境界を確認した。
