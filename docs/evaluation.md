# 評価の記録 ― 二つの軸

1問が終わるたびに、次の2つの評価を**別々に**記録します。

| 評価 | 誰が | 何を表すか |
|---|---|---|
| 自己評価 | 生徒 | 方針が浮かぶまでの時間、解答にたどり着くまでの時間から本人が感じた「復習の必要度」 |
| 教師評価 | AI | 実際の様子から見た「復習の必要度」 |

記号は◎〇△×で、**正誤ではなく復習の必要度**を表します（◎＝低い 〜 ×＝高い）。

| 記号 | 必要度 | 目安 |
|---|---|---|
| ◎ | 低 | 方針・実行ともにヒントなしで完遂 |
| 〇 | やや低 | 単発のつまずきをヒントで解消し、以後は自走できた |
| △ | 中〜やや高 | 過去にも記録のある型のミス、または複数回のヒントが必要だった |
| × | 高 | 方針が出てこなかった／方針自体が誤り（冒頭停止）、または実行しきれなかった（未達） |

## なぜ別々に記録するか

2つが食い違うこと自体が診断情報になります。
たとえば、本人は◎のつもりなのに教師評価が△なら、「できたつもり」になっている問題です。
逆に本人が×で教師が〇なら、必要以上に不安を感じているのかもしれません。

## 台帳に残す項目

| 項目 | 意味 |
|---|---|
| `outcome` | `correct` / `correctWithHints` / `correctRetry` / `failed`（レベル調整はこれだけを使う） |
| `teacher_eval`, `self_eval` | ◎〇△× |
| `stumble` | 最初に落ちた段：`reading`（読み取り）/ `approach`（方針）/ `execution`（実行）/ `verification`（検算）/ `none` |
| `error_category` | 計算ミス／公式の未定着／公式の誤適用／単位の取り違え／条件の取り違え／概念の誤解 |

- **評価の記号は、レベルの自動調整には使わない。** 調整は `outcome` だけで決める。
- **躓いた段は、最上流の1つだけを記録する。** 上流を直さないと下流のミスは再発するため。
- 「公式の未定着」（思い出せない）と「公式の誤適用」（思い出せたが当てはめを誤る）は、打ち手が違う（前者は暗記、後者は適用練習）ので分ける。

新規の追記は `teacher_eval`・`self_eval`・`stumble` を必須とします。
`stumble` が `none` 以外なら `error_category` も必須です。
分類のCLI語彙は `src/ledger.py` の `ERRORS` が正典です。単位と条件の取り違えを分けます。
旧台帳の評価欠損は読み取り可能ですが、診断で不足件数を表示します。
自己評価は本人の回答後に記録し、未回答を記号で補完しません。

## 新規記録の整合性

ヒント数`hints`はsessionの状態から取得する0〜3の整数です。新規記録では必須です。
自己評価は本人の主観であり、下表の教師評価との一致を強制しません。

| outcome | hints | stumble | 教師評価の制約 |
|---|---|---|---|
| correct | 0 | none | ×以外。過去の復習必要度を考慮して〇・△を付けることは可能 |
| correctWithHints | 1〜3 | none以外 | ◎不可。2回以上なら〇も不可 |
| correctRetry | 0〜3 | none以外 | 初回誤答を含むので◎不可。2ヒント以上なら〇も不可 |
| failed | 0〜3 | none以外 | ×のみ |

この表は、記録項目間の明白な矛盾を拒否するための入力条件です。
解答の採点と内容の確認は、人が行います。
例えば、支援後に解けても冒頭で方針が出なかった場合は教師評価×を付けられます。
ヒント数がない旧記録は推測で補完せず読み取ります。旧行の意味的整合性までは再検査しません。
