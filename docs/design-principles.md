# 設計の原則

実際に起きた失敗から、次の原則を作りました。

1. **演習手順と入力の整合性をCLIで検査する。**
   AIは長い会話の中でルールを忘れることがある。共通CLIで開始した問題は、未記録のまま
   次を開始できない。公式の追記入口をfinishに一本化し、ヒント数を含めて検査する。
   このCLIは、開始・ヒント・終了の手順と、評価の入力の整合性を検査する。
   解答の採点と内容の確認は、人が行う。
2. **記録は散文ではなく機械で読める形で残す。**
   横断した集計のために、共通の項目を設ける。実際に、ある時期の記録は「どの段で躓いたか」が1件もなかった。
   台帳（JSON Lines）に項目として残すことで、偏りや食い違いが見えるようになった。
3. **記録は1問ごと、その場で。**
   「後でまとめて」は抜けの原因になる。1問の判定が確定したら、すぐ記録する。
4. **分からないことを、分かったことにしない。**
   不確かなことは「未確認」と書く。完了の報告では、スキップした処理や未検証の前提も隠さない。
5. **状態は会話の中ではなくファイルに置く。**
   セッションが切れても、続きから再開できる。
6. **選ぶ作業は、条件をスクリプトに持たせる。**
   出題の候補は判定をスクリプトが行い、AIはその中から選ぶ。指定プール内の未演習問題を優先し、すべて演習済みなら最新の教師評価が△・×の問題を候補にする。
